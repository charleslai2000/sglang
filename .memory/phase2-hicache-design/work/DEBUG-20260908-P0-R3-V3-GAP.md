## Conclusion

R3 is not using a stale V2 deployment, and its durable-trace marker is active. The direct cause of the all-V2 event stream and the vehicle wait is a **runtime configuration/instrumentation activation gap**: the live engine was launched with `enable_session_radix_cache=false`. The V3 context path refuses to create a context without a scheduler-assigned `session_generation`; the scheduler only assigns that generation for a top-level `session_id` when session-radix cache is enabled. Consequently every durable record has no attached context, falls back to `p0_durable.v2`, and cannot produce a keyed V3 durability barrier.

The vehicle is correctly waiting: it rejects all 405 events at its schema gate before any session state can advance.

There is also a separately confirmed contract gap that will remain after configuration correction: no product-side `build_complete` V3 emitter was found, while the vehicle requires that event to establish its ordered build identity. Thus enabling the runtime flag is necessary to expose V3 contexts/barriers, but it is not by itself sufficient for this vehicle to issue a warm request.

## Reconstructed causal chain

1. The vehicle sends an explicit top-level `session_id` on each build request (`p0_session_barrier_vehicle.py:801-813`) and then waits for the V3 ordered barrier predicate (`:831-835`, `:343-354`).
2. The live engine configuration printed in its own startup log states `enable_session_radix_cache: False`; its argv has no corresponding enable flag.
3. Scheduler logic treats a top-level `session_id` as radix-native only when that flag is true, and assigns `req.session_generation` only in that branch (`scheduler.py:2638-2641`, `:2701-2704`). R3 therefore leaves the request generation unset.
4. The V3 context bridge returns `None` whenever `session_id` is absent *or* `session_generation is None` (`unified_radix_cache.py:686-713`). `make_trace_context` independently enforces the same condition (`trace_context.py:59-81`).
5. Node context recording then returns without binding a request context (`unified_radix_cache.py:840-866`). Durable logger calls invoke `attach_trace_context`, but with `trace_context=None`; the logger's `setdefault` consequently emits `p0_durable.v2`.
6. The V3 durability barrier code is conditional on `context_complete` plus KV and Mamba evidence (`unified_radix_cache.py:4657-4723`). Context-free R3 candidates therefore emit unkeyed V2 observations such as `storage_persisted`, but no V3 `durability_barrier`.
7. The vehicle rejects every V2 record immediately (`p0_session_barrier_vehicle.py:210-219`), so none can satisfy `ready_for_warm`; PID `999350` continues waiting.
