### HOST_ALLOC classification

Classification: **test fixture/API-contract mismatch or unresolved local source-version mismatch; not proven product failure**.

Evidence for the contract boundary:

- `HostAllocWakeArbiter.choose()` only grants the first eligible waiter for a vector (`hicache_restore.py:111-123`).
- Scheduler eligibility requires a current cache instance and a strictly advanced generation for every blocked domain (`scheduler.py:3481-3492`).
- The scheduler's grant vector is cache-owned and includes the current snapshot (`scheduler.py:3507-3511`, `:3616-3629`).

The exact minimal next step is **test-only investigation/correction by a coder**, not a product change: make the fixture obey the same cache snapshot/API semantics used by `_host_alloc_wait_eligible` and `_select_host_alloc_waiter`, then rerun only the three failing IDs. Do not weaken the production generation predicate or infer that free/evictable fields alone are wake events. A reviewer should compare the fixture's expected vector and blocked-domain setup with the production contract before accepting any assertion change.
