## 3. F2 — usable input length vs model ceiling

R60 records `context_len=262144` as "Context length" (original line 79) next to the
65536-token device KV pool (original line 80). Re-reading `r60_server_info.json` for this
amendment:

- live `r60_server_info.json` reports `max_req_input_len=65530` and `max_total_num_tokens=65536`;
- the string `262144` does **not** occur anywhere in `r60_server_info.json`; it appears only in
  the startup log (`log:42`) and, per R59, in the model config.

Correction:

- `context_len=262144` is the **model context ceiling** (`text_config.max_position_embeddings=262144`),
  not the usable single-request input length.
- The capacity-relevant usable single-request input cap is **`max_req_input_len=65530`**,
  consistent with the 65536-token device KV pool.

This amendment adds `max_req_input_len=65530` to the effective frozen capacity picture. R60's
context row is reworded to call `262144` the model ceiling and to point here; no existing R60
numeric value changes.
