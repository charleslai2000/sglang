## Summary

The opt-in CMake target shape is statically correct for the requested minimal
SM86 path, and the prior source/registration guard closure remains valid. The
change is rejected because the unconditional loader change regresses the
default-OFF 3090 package: default CMake still installs `sm90` and `sm100`, but
an SM86 GPU is now directed only to `sm86`.

This review makes no CUDA compilation, shared-object import, or runtime claim.

## Findings

### BLOCKER-1 — default-OFF 3090 loader path is incompatible with default artifacts

- **Severity:** blocker; acceptance-impacting compatibility regression.
- **Locations:**
  - `python/sglang/kernels/aot/python/sgl_kernel/load_utils.py:60-68`
  - `python/sglang/kernels/aot/CMakeLists.txt:117-123,375-399,426-444`
- **Evidence:**
  1. The new loader unconditionally maps `compute_capability == 86` to
     `ops_subdir = "sm86"` and constructs `sm86/common_ops.*`.
  2. With `SGL_KERNEL_MINIMAL_SM86=OFF`, the current CMake branch resolves the
     original `compute_90/sm_90` baseline and creates only
     `common_ops_sm90_build` and `common_ops_sm100_build`, with output/install
     paths `sm90` and `sm100`. There is no default-OFF `sm86` target or install
     destination.
  3. The default source block is byte-for-byte identical to the parent (50
     entries), and the default target/output/install paths remain the parent
     `sm90`/`sm100` paths. Thus the loader change, rather than a default build
     change, creates the mismatch.
  4. Independent loader mock for compute capability 86 with no `sm86` artifact
     recorded these probes only:
     `.../sgl_kernel/sm86/common_ops.*` and
     `.../sgl_kernel/common_ops.*`; it did not probe `sm100/common_ops.*`.
     This reproduces the expected failure against a default-OFF package.
- **Acceptance impact:** A normal default-OFF 3090 installation can no longer
  load its generated common library. This violates the requirement that the
  default 3090 source/target/path behavior be preserved and blocks acceptance
  before remote compilation.
- **Required disposition:** Make SM86 selection compatible with the build
  variant—e.g. preserve a safe default-package fallback to `sm100` while
  selecting `sm86` when the minimal artifact is present, or otherwise provide
  an explicit mode/artifact contract. Add an independent mock/static check for
  both minimal-SM86 and default-OFF-3090 dispatch, then request a fresh review
  Task ID.
