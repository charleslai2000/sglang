## 1. Conclusion (what the R105b "deadlock" actually was)

**The forward-pass deadlock was not a deadlock. It was a one-time, synchronous
JIT compile of the GPTQ-Marlin kernel on the first forward pass.**

On first forward, sglang calls its TVM-FFI/ninja JIT runtime to build
`sgl_kernel_jit_gptq_marlin_bf16_t` for `sm86` (`nvcc` + `cicc`, `-O3`). On this
host that build takes **~427 s (~7 min)** and blocks the scheduler thread (all
other threads futex-wait; GPU 0%; `/health` 503). Every prior R105 attempt
(including R105b attempt 6) killed the process at 75–150 s — i.e. *in the middle
of the build* — so it was misdiagnosed as a hang. Two orphaned `ninja`/`nvcc`
trees left behind by killed R108 attempts confirmed the build was live and
progressing (one `cicc` had 4:59 CPU time and was still in `R`).

Once the build is allowed to finish, the artifact
`sgl_kernel_jit_gptq_marlin_bf16_t.so` is cached, and the server serves real
generations in ~0.3 s. A subsequent cold launch reaches `/health` 200 in ~36 s.

With the JIT cache warm, **HiCache now advances past the first forward** and
fails later, for a different and precise reason: the HiCache native hash
extension cannot be built because the machine lacks OpenSSL development files
(`openssl/sha.h`, `libcrypto.so`). This was previously masked by the JIT build,
because the process was always killed before reaching the hashing path.

**Failing layer:** base model forward = **OK**; HiCache = **blocked (missing
`libssl-dev`)**; Ready Horizon = **untested** (depends on HiCache).

## 4. Why HiCache fails (exact dependency, verified)

- `hash_binding.cpp` needs `openssl/sha.h`; the venv has no OpenSSL headers and
  the system has only the runtime `libssl3t64` (`/usr/lib/x86_64-linux-gnu/libcrypto.so.3`),
  with **no `libssl-dev` and no `libcrypto.so` linker symlink**.
- `native_hash.py` builds with hardcoded `extra_ldflags=["-lcrypto"]`, and
  `get_hash_str()` (`mem_cache/utils.py:107-113`) calls the native module
  unconditionally — there is no pure-Python fallback.
- `sudo -n true` → `sudo: a password is required`; no privilege to install
  `libssl-dev`.
- `SGLANG_CACHE_DIR` JIT artifact for GPTQ-Marlin is now warm; HiCache's failure
  is therefore exposed rather than masked.
