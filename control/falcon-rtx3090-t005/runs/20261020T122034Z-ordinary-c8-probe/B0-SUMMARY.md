## Interpretations and limits
- Reproducible burst baseline B0 for this specific local Falcon/current-dirty runtime/64×256 workload: c32 client aggregate **726.14 ±1.07 output tok/s** over 3 trials. It is 73.7% of the owner-set RWKV reference threshold 985.1; not a cross-model performance equivalence.
- Actual hardware-independent service bottleneck not fully profiled yet. Direct decisive measured resource limit is Mamba state pool: `max_running_requests` forcibly reduced to 16 and decode graphs stop at 16 despite max graph/request flags 32. This is a strongly evidenced throughput limiter at client C≥24 (request P95 ~11.3s). B0 startup reports only 1.56 GB free after graph capture, so simply raising pool size could risk VRAM exhaustion. Do not accept state precision change without long-run state/logit/cache recovery oracle.
- Prefill CUDA Graph disabled in this run, so it is not the owner's requested all-graph-on launch. It matches the known successful current Falcon service configuration; full prefill graph enabling must be a separately tested config and report incomparable until confirmed. Decode graph fully enabled through BS16 only.
- FPM IPC socket was configured, but this run did not preserve its collector output or a standalone per-step server timeline; no per-step GPU busy/SM/Tensor/DRAM/stall causality claims. Server logs and client timings only; `/metrics` snapshot is available in metrics-final.txt. Sample time windows are disjoint within a single process; do not cross-join unrelated traces.
- Public RWKV script's output TPS wall clock excludes warmup; our table equally excludes one warmup per C, includes requests completion and tail. The script's printed per-request latency is not server E2E; we separately record server E2E median and client latency percentiles. The script allocates 4C requests. This baseline follows the same wall-clock numerator/denominator, and three runs are independent but in one service lifetime with no restart between C sweeps.
- Production HiCache long-context workload, Cache-OFF logit/state oracle, resource profiling, alternative capacity configs, matched optimization A/B, and c32 ≥985.1 remain unfinished. Do not call B0 ACCEPT or T005 done.
