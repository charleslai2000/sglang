Status: ACTIVE
Work area: `control/gemma4-rtx3090-throughput-scheduling` with runtime changes in the current repository worktree
Objective: Using the accepted T006 Owner-only FP8 E5M2 service/configuration and the original C-8 load, determine why NVML GPU use averaged 18.47%, Prefill batches contained 1–3 sequences, and aggregate throughput was 120.23 output tok/s; make and validate evidence-backed, contract-compatible performance improvements.

Completion: Same-load optimized and baseline measurements establish 800/800 correctness and output correctness; E2E throughput, TTFT/TPOT/E2E; actual Prefill/Decode batch distributions; GPU Forward duty, busy union and primary idle causes; effective L1/L2/L3, successful restoration and actual recompute; and a time/token ledger separating compute, transfer and idle. Explicitly test whether `SGLANG_ENABLE_METRICS_DEVICE_TIMER=1` takes effect in the service. Any changes are regression-tested and compared without reducing workload, cache functionality, or fixed-budget Owner-only KV settings. Store usable source-identified traces/reports; selectively commit/push task changes and verify remote SHA.
Result: Started. T006 baseline is 800/800 at 120.231 output tok/s, Full/SWA 1,443,024/65,536 slots, and unchanged T006 resource settings. Existing data show decode logs at high batch TPS but do not form an end-to-end compute/idle ledger. In the C-8 service, startup `fwd_occupancy` was NaN and no timer env evidence appeared in its manifest/logs; this does not establish whether the env was absent, ineffective, or simply not sampled under the interval window. Source code shows the env defaults false; metrics reporter creates DeviceTimer only when true, and capture requires actual imported source/runtime evidence. This is the first instrumentation verification item, not a claim that timer support is broken.
Remaining: Inspect existing tool and source patterns, prove DeviceTimer/FPM/NVTX activation and export in the exact runtime, then use bounded same-service workload sampling to attribute idle/prefill batching and ledger phases. No optimization accepted yet; avoid speculative scheduler changes.
