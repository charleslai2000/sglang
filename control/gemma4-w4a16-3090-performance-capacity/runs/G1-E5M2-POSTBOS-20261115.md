# G1 E5M2-KV GSM8K after explicit-BOS restoration — 2026-11-15

## Result

Full GSM8K official test split, n=1,319, run on W4A16 INT4 group32 weights with `fp8_e5m2` KV. The run is paired itemwise with the already accepted explicit-BOS BF16-KV corpus; BF16 was not rerun. Both used the same checkpoint revision `6cd26aaa2357fb2bad8c51699a7558a4d1a965bb`, weight SHA-256 `19d89d2a4b3e401a3eae75ec08ab112810421a036c91d8c8226b686be7fe0c5d`, exact BOS protocol (`prompt_ids[0] == 2`), prompt token IDs, five few-shot examples, greedy decoding, stop strings, and lm-eval scoring implementation.

- BF16 KV: **1,079/1,319 = 81.804%**.
- E5M2 KV: **1,067/1,319 = 80.895%**.
- Paired cells (BF16 correct / E5M2 correct): both correct **1,026**; both wrong **199**; BF16 only **53**; E5M2 only **41**.
- Paired accuracy delta E5M2−BF16: **−0.910 percentage points**. Paired item bootstrap 95% percentile interval: **[−2.350, +0.531] pp** (20,000 replicates, seed 20261114). This interval concerns GSM8K exact-match outcomes only; it is not a numerical-correctness bound.
- Greedy output token sequence differed on **772/1,319 (58.53%)** items; decoded response text differed on the same **772**. Prompt token IDs matched on all 1,319.
- Stop audit: 1,318 finished by stop; one reached length limit. Stop strings: 1,297 `Question:`, 21 EOS token ID 106; one length-limited completion had no matched stop. This differs from BF16's stop mix and should be retained as an observed generation-protocol outcome, not hidden by the aggregate score.

Conclusion: Full post-BOS E5M2 GSM8K pairing is complete. The score is close, but 772 sequence divergences and the lack of aligned logits prevent any numerical-equivalence claim. **E5M2 remains NOT ACCEPTED; BF16 KV remains default.** This result does not close the N=512/513/514 guards.

These are historical report assertions, not artifacts independently remeasured in this run. No defect is confirmed here; no fix/retest is claimed.
